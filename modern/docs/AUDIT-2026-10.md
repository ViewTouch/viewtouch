# Code audit, October 2026

A read through the modern ViewTouch for bugs, reliability and speed. What was
fixed is on the `claude/audit-fixes` branch, one commit per fix, each with a
test. What is left needs a decision first (it changes saved data or is a
larger rework).

## Needs a decision

- **Past tax at today's rates.** Reports over a range, the dashboard and expected cash work out tax again with today's rates (`core/report.cpp`, `app/pos_dashboard.cpp`). After a rate change, earlier periods show the wrong tax. The fix is to save each closed check's tax as it closed: a change to saved data. Days already closed keep their saved reports and aren't affected.
- **Doubles for labor, tip pools and stock.** Labor cost rows are rounded separately from their total, tip pool shares are split in floating point, and ingredient amounts are doubles (`core/report.cpp`, `core/inventory.hh`). The drift is cents, but integer units would end it; that touches saved data.
- **Work on the screen's thread.** The standby's full copy (backup, read, base64) runs on the main thread and sends at once, about 1.4× the database in memory (`main.cpp`, `net/pos_server.cpp`); when the backup fails it still marks the standby in sync. The dashboard's history every 5 minutes and Forget Customer also read the database there. These should move to a worker.
- **One signal for 33 properties.** `adminChanged` refreshes the whole menu and every manager list in QML on any change, a sold-out mark too (`app/pos_session.hh`). Splitting it (menu, staff, settings) would cut work on every screen.
- **Kitchen display.** Each ticket change rebuilds every card, and draws each ticket a second time to measure it (`ui/qml/WidgetKitchenDisplay.qml`). A model updated in place would keep busy kitchens smooth.
- **Startup reads every time punch ever** (`storage/pos_store.cpp`, `PosStore::load`), and `load()` reads its ~30 tables without one read transaction.
- **Compiler warnings.** The build has no `-Wall -Wextra`; turning them on (without `-Werror`) would catch mistakes early.
- **Large files.** `WidgetMenuBuilder.qml` (2,300 lines), `layoutcontroller.cpp`, `pos_service.cpp` and `main.cpp` (over 2,000 each) would be easier to change split up.

## Checked and fine

Money is integer cents with explicit rounding. Commands from terminals use
defaults and clamp their values. Range reports run on a thread pool. The
server only takes TLS-PSK connections from paired devices.

## Tests

The full suite (about 675 test cases) passes on each branch, except
`UI: Menu Builder: a ready-made picture…`, which needs the color emoji font
(`fonts-noto-color-emoji`, installed in CI): on a machine without it, it
fails whatever the branch.
