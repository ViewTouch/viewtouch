# Code audit, October 2026

A read through the modern ViewTouch for bugs, reliability and speed. What was
fixed first is below, one commit per fix, each with a test; then what was
left, done since (October 2026), and the two left on purpose.

## Fixed

| Area | What was wrong | Where |
|---|---|---|
| Tax | A percent discount lowered the tax on lines it didn't come off: $10 food and $10 wine that can't be discounted, 50% off, taxed each on $7.50. | `core/core.cpp` (`Check::totals`) |
| Receipts | With discounts capped at the items total, each discount's own line on the receipt wasn't, so the lines added up to more than came off. | `core/core.cpp` |
| Database | A row SQLite would always refuse held up every later write for good; sales piled up in memory. It is now set aside in `<database>.unsaved.jsonl` after five tries and the manager is told. Retries back off to a minute; a statement is prepared once per batch, not per row. | `storage/async_writer.cpp` |
| Database | A stop between adding the cash tips column and moving the schema version left a database no later start would open. | `storage/pos_store.cpp` (migration 13) |
| Database | Lookups by time on punches, refunds, shifts, deliveries, problems and parties read whole tables. Indexes are made on opening (not a schema version, so a standby a version behind still opens it). | `storage/pos_store.cpp` |
| Standby | Table and column names from the main server's messages went into SQL text as they came. Only plain names are taken now. | `storage/async_writer.cpp` |
| Standby | No limit on PIN tries to take over. After five wrong ones it waits 30 s, doubling to 15 minutes. | `net/standby.cpp` |
| Network | A long message arriving in pieces was searched from its start for each piece (quadratic). A runaway line on the standby and pairing connections grew without limit. | `net/protocol.cpp` |
| Network | Terminals retried every 2 s forever, and a try to an address nothing answered waited minutes. Now a short backoff to 10 s and a 10 s connect timeout. A discovery answer with an impossible port is ignored. | `net/remote_session.cpp`, `net/discovery.cpp` |
| Offline | A screen's offline check sent again after End of Day was booked a second time. | `app/pos_offline.cpp` |
| Forms | Numbers typed with a comma for the decimals ("18,5") read as 0 or were refused on the manager screens (prices already took them). | `app/pos_admin_shared.hh`, `app/pos_admin_save.cpp` |
| Import | A sheet with both Cost and Price columns imported whichever came first as the price. | `app/menu_import.cpp` (on `claude/retail-stock`) |
| Scanning | A UPC read as an EAN-13 (a 0 in front) didn't ring the item in on the order screen, though the rest of ViewTouch matched it. | `ui/cpp/layoutcontroller.cpp` (on `claude/retail-stock`) |
| Page editor | "Opens on" for a report view was missing four reports. | `layout/schema.cpp` (on `claude/report-side-list`) |

| Labor rounding | Each row of Labor cost is in cents and the total is what the rows add up to (it rounded the sum once: three rows of $5.01 under a $15.02 total). | `core/report.cpp` |

Found while testing since, and fixed: the home screen waited on `timedatectl` and `systemctl` every 10 s (now in the background); the picture picker's USB Stick button froze the screen up to 15 s; the Now Serving board rebuilt its columns with every order, so a rush never got past its first page.

## Left, on purpose

- **The stock screens' signal.** Receiving, stock counts and the waste log still refresh with `adminChanged`. They change a few times a day; a signal of their own would touch the network protocol of every screen for no felt gain.
- **Large files.** `WidgetMenuBuilder.qml` (2,600 lines), `layoutcontroller.cpp`, `pos_service.cpp` and `main.cpp` (over 2,000 each). Splitting them changes nothing a store sees and puts the busiest screens at risk; better done a piece at a time when a change is being made there anyway.

## Round 3: bugs the tests couldn't see (November 2026)

Tools added: builds with sanitizers and coverage (`-DVTM_SANITIZE=address,undefined`,
`-DVTM_COVERAGE=ON`, `tools/coverage.py`); a QML warning in any test fails the
run; fuzzers in the suite (`tests/test_fuzz.cpp`, more rounds with
`VTM_FUZZ_ROUNDS`); daylight-saving tests (`tests/test_time.cpp`); a four-month
soak (`tests/test_soak.cpp`); a CI workflow running the suite under ASan and
UBSan on every push to main (`.github/workflows/modern-sanitizers.yml`).

| How it was found | What was wrong | Where |
|---|---|---|
| Fuzzing commands | A kitchen screen's station took any text (5,000 characters, kept in the settings). | `app/pos_kitchen.cpp` |
| Fuzzing commands | A table could be opened with an empty name or a page of text. | `app/pos_service.cpp` |
| Fuzzing commands | Posted messages had no limit: as many as sent, kept until the year 292 million, in the settings every screen gets. | `app/pos_service.cpp` |
| Fuzzing the network | A check sent as taken offline, "closed" but not paid in full, went into the day's sales with money owed. It comes in open now. | `app/pos_offline.cpp` |
| Reading the offline intake | A screen's own tax rates were taken as sent (an old or wrong copy could close checks untaxed). The store's rates now. | `app/pos_offline.cpp` |
| Fuzzing the import | A price of "inf" or "1e300" (any price typed, cash tips too) was rounded to cents: undefined behavior. A $99,999,999,999,999 price imported. | `app/pos_menu_builder.cpp`, `app/menu_import.cpp` |
| Fuzzing backups | Two restores in one second clashed; and a restore whose -wal didn't move left the store with no database. | `storage/backup.cpp` |
| UBSan, fuzzing saved records | A damaged record's huge amount overflowed 64 bits working out tax. Saved numbers are held to sane ranges; `Money::scaled` can't overflow. | `app/pos_json.cpp`, `core/money.hh` |
| Daylight-saving tests | Time off on the 25-hour day missed a shift at 11:15 PM. | `app/pos_requests.cpp` |
| Clock tests | With the clock set back, orders showed waiting -9 minutes. | `app/pos_truck.cpp` |
| The soak | A register on for months kept every bumped ticket, delivery, finished party and closed day's reports in memory: lists that grew every day (and were walked or sent to the screens). | `app/pos_day.cpp` |

Checked and clean: the whole suite and the real program (a busy dinner over
the network, months of demo history) under AddressSanitizer,
UndefinedBehaviorSanitizer and LeakSanitizer; 3,000 rounds of random commands
(1.8 million calls; a server never changes settings, staff or the menu);
120,000 commands from a manager aimed at a check another screen is paying
(it holds); qmllint (its findings were false alarms: a Repeater's delegates'
parent is the layout, not the Repeater); no QML warning in any test; a
store saved by 0.13 opens and its End of Day matches line for line; shifts
across both daylight-saving changes count the hours worked; a newer main
(a standby that took over) makes the old one step down while running.

Coverage: the tests run 86% of the lines (94% of `app/` and `core/`,
where the money is). Most of what isn't run is the stress test itself,
`main.cpp`'s command-line paths and the home screen's system commands
(tested against a pretend helper). The database's own reads and deletes
that no test ran are tested now.

## Checked and fine

Money is integer cents with explicit rounding. Commands from terminals use
defaults and clamp their values. Range reports run on a thread pool. The
server only takes TLS-PSK connections from paired devices.

## Tests

The full suite (over 700 test cases) passes, on Qt 6.10 here and Qt 6.8 in
CI. Since this audit it also runs the real program: a restore from start to
finish, a store saved by 0.13 opened and its End of Day checked line for line,
a board on its own computer, four days of books against their range report.
`UI: Menu Builder: a ready-made picture…` needs the color emoji font
(`fonts-noto-color-emoji`, installed in CI).
